## 第一部分 任务要求（用户提出的口径）

### 1.1 总体要求

> 评分模型搭建：构造标签、划分训练 / 测试集、训练 Logistic/SVM/RandomForest/XGBoost 并评估。

**用 Logistic 回归做精度基线，随机森林做对比，XGBoost 作为最终上线模型**；人岗匹配是典型的结构化特征分类任务，梯度提升树模型（XGBoost）天然适配。

### 1.2 标签构造要求（正负样本）

基于业务规则给每一对 <简历, 岗位> 打标签：

**正样本（标签 = 1，匹配）**：同时满足 4 个核心门槛
1. 居住地与岗位城市距离在 300km 以内；
2. 简历学历满足岗位最低学历要求；
3. 工作经验年限满足岗位要求区间；
4. 至少命中岗位 **1 个及以上**核心技能。

**负样本（标签 = 0，不匹配）**：满足以下任意一种
1. 随机错位配对（简历和随机岗位匹配）；
2. 至少 2 个核心维度完全不满足。

> 正负样本比例控制在 **1:1 ~ 1:1.5**，避免样本不平衡导致模型偏向多数类。

### 1.3 特征要求

| 特征类别 | 具体特征 | 计算方式 |
|---|---|---|
| 基础属性匹配 | 城市匹配度 | 0/1（居住地与岗位城市距离在 300km 以内为 1） |
| | 学历匹配度 | 0/1/2（不满足 / 刚好满足 / 超出要求） |
| | 经验匹配度 | 经验差值的归一化值，或 0/1（是否满足最低年限） |
| 技能匹配特征 | 技能 Jaccard 相似度 | 简历技能 ∩ 岗位技能 / 简历技能 ∪ 岗位技能 |
| | 核心技能命中率 | 岗位要求的核心技能中，简历具备的数量占比 |
| | 技能覆盖度 | 简历技能覆盖岗位要求技能的比例 |
| 文本语义匹配 | 岗位-经历文本相似度 | 岗位描述 vs 简历工作/项目经历，TF-IDF 余弦相似度 |
| | 岗位-求职意向相似度 | 岗位名称 vs 简历求职意向，文本相似度 |
| 附加特征 | 专业匹配度 | 0/1（专业是否对口） |
| | 证书命中数 | 岗位要求证书的命中数量 |

## 第二部分 实现过程

### 2.1 数据来源与规模

| 数据 | 规模 | 说明 |
|---|---|---|
| 岗位数据 | 8,836 条 × 15 列 | 任务3 清洗结果（已删 `城市(实测)` 列），另有分词版 17 列 |
| 简历数据 | 500 份 × 44 列 | 任务3 简历清洗+结构化结果（含 `最高学历`、`工作年限`、`技能列表`、`专业` 等派生列） |
| 配对样本 | **153,872 条** | 正 69,942 / 负 83,930 |

### 2.2 标签构造（`src/models/scoring/build_labels.py`）

四个门槛的落地口径（保证全流程一致）：

| 门槛 | 落地实现 |
|---|---|
| ① 距离 ≤300km | 25 个城市经纬度 + haversine 球面直线距离；坐标表 `data/external/城市坐标.csv` |
| ② 学历满足 | 学历序数化：高中 2 < 中专/中技 3 < 大专 4 < 本科 5 < 硕士 6 < 博士 7；要求 `简历序数 ≥ 岗位序数`；岗位该列为空视为“不限” |
| ③ 经验满足 | 岗位 `经验要求` → 区间（1-3年→[1,3]、3-5年→[3,5]、5-10年→[5,10]、10年以上→[10,∞)、不限/未标注→不设门槛）；简历 `工作年限`（应届=0）须落在区间内 |
| ④ 技能命中 ≥1 | **岗位核心技能 = `技能标签` 字段 ∪ `职位描述`（jieba 分词结果）中出现的技能词**；技能词以**简历技能池（74 项技术词）**为词典识别；命中数 = 简历技能 ∩ 岗位核心技能 |

**技能口径说明**：若只统计 `技能标签` 字段，全库仅极少数岗位能与简历池命中（该字段大量是 QE/QC/QA、行业词等非技术词），因此把“职位描述中提到的技能词”一并计入岗位核心技能。两种口径的正样本数对比：仅标签口径 **19,980** 个 → 标签+描述口径 **69,942** 个。

**样本规模与平衡**：

| 项目 | 数量 | 占比 |
|---|---|---|
| 正样本（标签=1） | 69,942 | 45.45% |
| 负样本（标签=0） | 83,930 | 54.55% |
| **合计** | **153,872** | 100% |
| 正负比 | **1 : 1.20** | 符合 1:1 ~ 1:1.5 |

- 负样本来源各半：随机错位配对 **41,965** + 至少 2 个维度不满足 **41,965**；
- 随机配对中“恰好满足全部 4 个门槛”的对数 = **0**（不会错标）；
- 未满足维度数分布：1 项 6,617（难负样本）、2 项 37,726、3 项 32,210、4 项 7,377；
- 距离门槛合格的候选对 1,350,544 个，其中不满足率：学历 23.94%、经验 52.68%、技能命中<1 占 84.89%（技能是主要瓶颈）。

### 2.3 特征构造（`src/models/scoring/build_features.py`）

按 1.3 的要求实现 12 个特征（口径细节）：

| 特征 | 实现细节 |
|---|---|
| 城市匹配度 | 0/1：距离 ≤300km 记 1 |
| 学历匹配度 | 学历序数差 = 简历 − 岗位：<0 → 0 不满足；=0 → 1 刚好满足；>0 → 2 超出要求 |
| 经验是否满足 | 0/1：工作年限是否落在岗位经验区间 |
| 经验差值 / 归一化 | 差值 = 简历年限 − 岗位最低年限；归一化 = 差值 ÷ 5，截断到 [-1, 2]（两个都保留，可二选一） |
| 技能 Jaccard | \|简历技能 ∩ 岗位核心技能\| ÷ \|并集\| |
| 核心技能命中率 | \|命中\| ÷ \|岗位核心技能\|（岗位视角） |
| 技能覆盖度 | \|命中\| ÷ \|简历技能\|（简历视角，避免与命中率线性重复） |
| 岗位-经历文本相似度 | TF-IDF 余弦：岗位 `描述分词`（jieba 已有列） vs 简历`工作/实践经历+项目经验`分词；词级词表 31,853 维 |
| 岗位-求职意向相似度 | TF-IDF 余弦：岗位名称 vs 简历期望岗位；字符 2-3gram 词表 32,866 维 |
| 专业匹配度 | 0/1：岗位名称关键词 → 对口专业关键词规则表（计算机/电子/机械三大类）→ 简历专业是否命中 |
| 证书命中数 | 岗位描述中识别到的证书要求（12 类证书关键词）∩ 简历持有证书个数 |

**单特征区分力（单特征 AUC）**：

| 特征 | 正样本均值 | 负样本均值 | 单特征 AUC |
|---|---|---|---|
| 城市匹配度 | 1.0000 | 0.2496 | 0.8752 |
| 学历匹配度 | 1.2326 | 1.0443 | 0.5642 |
| 经验是否满足 | 1.0000 | 0.4165 | 0.7917 |
| 经验差值 | 1.7730 | −0.1800 | 0.7236 |
| 经验差值归一化 | 0.3546 | −0.0272 | 0.7236 |
| **技能Jaccard** | 0.1191 | 0.0136 | **0.9419** |
| **核心技能命中率** | 0.2656 | 0.0274 | **0.9489** |
| **技能覆盖度** | 0.1932 | 0.0239 | **0.9361** |
| 岗位-经历文本相似度 | 0.0264 | 0.0135 | 0.6936 |
| 岗位-求职意向相似度 | 0.0842 | 0.0350 | 0.6486 |
| 专业匹配度 | 0.8161 | 0.5037 | 0.6562 |
| 证书命中数 | 0.0030 | 0.0023 | **0.5004（弱特征）** |

> 技能类三个特征区分力最强（AUC 0.94~0.95）；证书命中数因仅 226/8,836 个岗位提到证书要求而几乎无区分力（99.74% 样本为 0），保留但在建模说明中标注其贡献有限。

### 2.4 数据集划分（重点：防止数据泄漏）

同一份简历会产生几十~几百条配对、同一岗位也会出现在多条配对中；若按行随机划分，模型会“背下”简历/岗位的个体特征，指标虚高。因此采用**严格划分**：简历与岗位两侧都不重叠。

| 口径 | 训练集 | 验证集 | 测试集 | 简历重叠 | 岗位重叠 |
|---|---|---|---|---|---|
| **严格划分（主口径）** | **69,617** | **2,238** | **6,609** | 0 | 0 |
| 参考划分（对比用） | 87,715 | 2,862 | 31,432 | 0 | 8,007 |

- 严格划分 = 训练简历 × 训练岗位；测试 = 测试简历 × 测试岗位；两侧交叉的 50,518 条配对与训练池内交叉的 24,890 条配对**不使用**；
- 验证集在训练池内再切 15%，**简历与岗位都与训练集不重叠**，只用于 XGBoost 早停与阈值选择；
- 三份划分的简历/岗位重叠经断言校验**全部为 0**，且三份 + 未使用 = 153,872；
- 划分文件已落盘：`数据集划分_训练集.csv`、`数据集划分_验证集.csv`、`数据集划分_测试集.csv`（`src/models/scoring/split_dataset.py` 生成，种子 42，可复现）。

### 2.5 模型训练与调参（`src/models/scoring/train_models.py`）

| 模型 | 配置 | 定位 |
|---|---|---|
| Logistic 回归 | StandardScaler + LogisticRegression(max_iter=2000, C=1.0) | **精度基线**（线性、可解释） |
| SVM | StandardScaler + LinearSVC(C=1.0, max_iter=5000) | 对比（样本量大，采用线性核） |
| 随机森林 | n_estimators=300, n_jobs=-1 | 对比（非线性、抗噪） |
| **XGBoost** | 网格调参后：max_depth=6, learning_rate=0.1, n_estimators=300（早停 249）、subsample/colsample=0.8、tree_method=hist | **最终上线模型** |

- XGBoost 做了 7 组小网格调参（max_depth 4/6/8/10/12 × learning_rate 0.05/0.10），**按验证集 F1→AUC 选最优**（记录见 `data/processed/模型调参记录.csv`），测试集全程不参与调参；
- 决策阈值按验证集 F1 网格搜索，推荐阈值 **0.5**（模型概率高度饱和：正样本概率≈1、负样本≈0，阈值不敏感）；
- 最终上线模型用**全量 153,872 条样本**重训（n_estimators=249）。

### 3.1 严格划分测试集（6,609 条）

### 3.4 特征重要性（Top）

| 排名 | XGBoost（严格划分） | 重要性 | 随机森林 | 重要性 |
|---|---|---|---|---|
| 1 | 技能Jaccard | 0.6280 | 技能Jaccard | 0.2657 |
| 2 | 城市匹配度 | 0.1636 | 核心技能命中率 | 0.2107 |
| 3 | 核心技能命中率 | 0.1171 | 技能覆盖度 | 0.1817 |

> 两个模型一致认为**技能类特征**与**城市匹配度**最关键，与业务直觉一致；文本相似度、专业匹配度、证书命中数的贡献很小（在规则标签下可忽略）。

### 3.5 结论

1. **Logistic 回归（精度基线）**：Accuracy 0.9980、ROC-AUC 0.9983，说明 4 个门槛类特征本身判别力很强；其价值在于线性权重可解释、可作为基线衡量树模型的增益。
2. **SVM（线性核）与随机森林（对比）**：线性核 SVM 与 Logistic 基本持平；随机森林自动捕捉特征的非线性与交互，指标直接触顶，训练仅需约 1 秒。
3. **XGBoost（最终上线模型）**：Accuracy/Precision/Recall/F1/ROC-AUC **全部 1.0000**，训练 0.31s、预测 0.015s，模型 104 KB JSON 可直接部署。选它上线的工程理由：训练/推理更快、支持早停与阈值控制（输出概率）、模型体积小易服务化、对新增特征与噪声更稳。
4. **必须如实说明的一点**：本任务的标签是由 4 条业务规则**生成**的，且 4 个门槛特征本身就在特征集合里，因此**随机森林与 XGBoost 都触到了上限、并列最优**，“XGBoost 显著优于随机森林”在这份规则标签数据上无法成立；XGBoost 相对线性模型（0.9980）的领先是真实的，在难样本子集上更明显（AUC 1.0000 vs 0.9777/0.9729）。
5. **想让模型差距拉开**，可采用的后续方案：① 把 4 个门槛特征从特征集移除，仅用文本/技能特征建模；② 引入只差 1 项门槛的近似岗位作为难负样本；③ 加入人工标注样本。这三种设置下梯度提升树通常会明显领先。

### 4.2 推理用法

```python
import json, pandas as pd
from xgboost import XGBClassifier

meta = json.load(open('models/model_metadata.json', encoding='utf-8'))
clf = XGBClassifier(); clf.load_model('models/xgboost_scoring_model.json')

X = pairs[meta['features']]                      # 必须按 meta['features'] 顺序构造 12 维特征
prob = clf.predict_proba(X)[:, 1]                # 匹配概率
score = (prob * 100).round(1)                    # 映射为 0~100 的匹配得分
label = (prob >= meta['recommended_threshold']).astype(int)   # 是否匹配
```

## 附录 B 术语与说明

- **严格划分**：训练集与测试集在简历、岗位两个维度都不重叠，用于避免配对记忆带来的指标虚高；
- **难负样本**：只差 1 个核心门槛的负样本，最容易被误判为匹配；
- **岗位核心技能**：`技能标签` ∪ 职位描述中命中简历技能池（74 项技术词）的技能词；
- **匹配得分**：模型输出的匹配概率 × 100，用于推荐列表排序。
