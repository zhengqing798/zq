# 环境搭建与运行指南（从 clone 到跑起来）

> 面向**从 GitHub 克隆本项目的人**。按本文 6 步走，可在 10~15 分钟内得到与本机一致的运行环境。
> 遇到问题先跑体检脚本：**`python scripts/doctor.py`** —— 它会逐项告诉你缺什么、用什么命令补。

---

## 0. 先理解一件事：为什么仓库只有 ~105 MB，而本机有 1.2 GB

这是**有意为之**，不是仓库不完整。差异构成如下：

| 本机占用 | 是否入库 | 说明 |
|---|---|---|
| `.zhaopin_profile/` **698 MB** | ❌ | 爬虫用的 Chrome 用户数据目录（登录态/缓存）——**跟运行项目无关**，可整个删掉 |
| `.venv/` **199 MB** | ❌ | 虚拟环境，用 `requirements.txt` 重建 |
| `data/` **192 MB** | 部分 | 见下面两张表 |
| `.zhaopin_anon/` **46 MB** | ❌ | 另一个 Chrome profile，同样无关 |
| `reports/` 6 MB + `models/` 1.7 MB | ✅ | 图表与上线模型，已入库 |

**已入库（173 个文件，约 105 MB）—— 克隆后就在**：

| 文件 | 大小 | 作用 |
|---|---|---|
| `data/processed/zhaopin_jobs_cleaned_seg.csv` | 21.5 MB | **岗位分词表 8,836 行**（全系统根数据） |
| `data/raw/zhaopin_jobs_full.csv` | 18.5 MB | 任务2 爬取原始数据 |
| `data/processed/zhaopin_jobs_cleaned.csv` | 13.0 MB | 清洗后岗位表 |
| `data/processed/RAG_知识卡.csv` | 6.9 MB | RAG 全部卡片（可审计） |
| `data/processed/匹配样本_划分_按{简历,岗位}.csv` | 3.5 + 3.5 MB | 任务5 数据划分 |
| `data/processed/简历数据_{cleaned,seg}.csv` | 1.1 + 1.4 MB | 简历 500 份（结构化 + 分词） |
| `models/*.joblib` ×4 + `模型元数据.json` | 1.7 MB | 上线 XGBoost 模型 |
| `data/processed/技能同义词表.csv`、`技能词典_匹配用.csv` | 0.2 MB | 技能归一与词典（3,975 词） |
| `docs/`、`src/`、`reports/figures/` | — | 全部文档、源码、16 张图 |

**未入库（5 个，共约 95 MB）—— 但都能一键重建**：

| 文件 | 大小 | 重建命令 | 预计耗时 |
|---|---|---|---|
| `data/processed/匹配样本_标签数据.csv` | 27.4 MB | `python src/models/scoring/build_labels.py` | 1~3 min |
| `data/processed/匹配特征_全量样本.csv` | 25.5 MB | `python src/models/scoring/build_features.py` | 1~2 min |
| `data/rag/jobs_kb_vectors.npy` | 17.3 MB | `python src/rag/build_kb.py` | 2~5 min（含首次下载） |
| `data/rag/embeddings_8852_512.npy` | 17.3 MB | 同上 | 同上 |
| `data/rag/jobs_kb_cards.json` | 8.0 MB | 同上 | 同上 |

> **为什么不入库**：这 5 个文件是 8,836 岗 × 500 简历 的派生产物，体积大且**完全可由脚本确定性重建**（固定随机种子 42）。放仓库会让 clone 变慢、且每次重跑都会产生无意义的 diff。
>
> **另外不在仓库里的两样**（都不是"缺失"）：
> - **`.env`**：内含 DeepSeek API Key，**出于安全绝不入库**（已在 `.gitignore`）。需要你自己建。
> - **BGE Embedding 模型**（约 92 MB）：存在用户级缓存 `~/.cache/huggingface/`，首次运行自动从 `hf-mirror.com` 下载。

## 2. 六步跑起来

### 第 1 步：克隆

```bash
git clone https://github.com/zhengqing798/zq.git
cd zq
```

### 第 2 步：建虚拟环境并装依赖

```bash
python -m venv .venv

# Windows PowerShell
.venv\Scripts\Activate.ps1
# macOS / Linux
# source .venv/bin/activate

pip install -r requirements.txt
```

国内网络慢可加镜像：
```bash
pip install -r requirements.txt -i https://mirrors.cloud.tencent.com/pypi/simple/
```

> `requirements.txt` 里 `chromadb` / `sentence-transformers` / `openai` 是**早期评估过但最终未采用**的依赖
> （见《大模型应用文档》第二节的选型说明）。装不上可以直接跳过，本项目实际用的是
> **faiss-cpu + torch + transformers + requests**。

### 第 3 步：配置 `.env`（跑 Agent 才需要）

在**项目根目录**新建 `.env`：

```ini
DEEPSEEK_API_KEY=sk-你的key
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-chat
```

> `.env` 已在 `.gitignore` 中，**不会被提交**。
> `DEEPSEEK_MODEL` 写 `deepseek-chat` 即可（服务端会解析到 `deepseek-flash`），**不要**为了统一名字去改它——改了会导致 Agent 缓存全部失效。

### 第 4 步：体检

```bash
python scripts/doctor.py
```

它会逐项检查 Python 版本 / 15 个依赖包 / `.env` / 根数据 / 4 个模型 / 5 个派生文件 / BGE 模型缓存，
并**直接打印缺失项的修复命令**。本机（数据齐全时）输出：

```
✅ 体检通过：环境和数据齐备，可以直接跑。
```

### 第 5 步：重建那 5 个派生产物（按顺序）

```bash
python src/models/scoring/build_labels.py     # → 匹配样本_标签数据.csv（207,640 行配对，约 1~3 min）
python src/models/scoring/build_features.py   # → 匹配特征_全量样本.csv（36 维特征，约 1~2 min）
python src/rag/build_kb.py                    # → RAG 向量 + 卡片元数据（首次下载 BGE ~92MB，约 2~5 min）
```

> **只想跑 Agent 问答 / 人岗匹配**？那只跑**第 3 条** `build_kb.py` 就够了。
> 前两条只影响「复现任务5 评分模型 / 任务8 多模型对比」。

### 第 6 步：验证

```bash
# ① Agent 智能问答（最能说明问题的一句：它会如实报数量并标注来源）
python src/agent/agent.py --ask "福州市的Java岗位有多少个？"

# ② 粘贴简历做人岗匹配（返回 Top-N + 六维分 + 推荐理由）
python src/models/matching/match.py --text "大专 3 年软件测试 Selenium JMeter Python MySQL 期望苏州" --top 5

# ③ 交互式连续提问
python src/agent/agent.py --repl
```

**预期输出（①）**：先打印工具调用轨迹，再给出带来源的中文回答，最后一行是
`（工具 N 次 ｜ N 轮 ｜ N.Ns ｜ tokens {...} ｜ 缓存命中：False）`。

## 4. 常见问题

| 现象 | 原因与解决 |
|---|---|
| `ModuleNotFoundError: No module named 'faiss'` | `pip install faiss-cpu`（注意不是 `faiss`，后者在 Windows 上常编译失败） |
| `缺少 .env 里的 DEEPSEEK_API_KEY` | `.env` 不在**项目根目录**，或文件名/键名写错 |
| 首次跑 `build_kb.py` 卡在下载 | 正常，正在从 `hf-mirror.com` 下 BGE（约 92 MB）。脚本已内置镜像设置 |
| `DeepSeek 调用失败：HTTP 401 / 402` | Key 无效 / 余额不足 |
| 终端里中文乱码 | 用 **Windows Terminal**（而非老版 conhost），或先执行 `chcp 65001` |
| `faiss.write_index` 报无法打开文件 | 已知问题：FAISS 的 C++ 层**不支持中文路径**。本项目已改为**向量存 `.npy`、索引启动时内存重建**，无需处理 |
| 想省磁盘 | `.zhaopin_profile/`、`.zhaopin_anon/` 共 744 MB 是**爬虫浏览器缓存，可安全删除** |
| 提问秒回、`缓存命中：True` | 命中了 `data/rag/agent_cache.json`；加 `--no-cache` 强制真实调用 |

## 5. 复现一致性说明（如实标注）

| 项 | 说明 |
|---|---|
| 随机种子 | 配对抽样、划分、聚类的种子**固定为 42**，重建结果与仓库内报告一致 |
| 版本敏感项 | `scikit-learn` / `xgboost` 版本不同时，模型指标可能有微小差异；报告中的数字基于 **sklearn 1.6.0 + xgboost 3.4.1** |
| 向量检索 | BGE 模型与 8,852 张卡片的顺序固定，重建的向量矩阵与仓库报告中的召回指标一致 |
| Agent 回答 | 大模型输出**不保证逐字一致**（即使 `temperature=0`）；但工具调用轨迹与数字应当一致，且都带来源 |
| 未入库的两类 | `.env`（密钥）与 BGE 模型（92 MB 缓存）必须各自准备，无法从仓库获得 |
