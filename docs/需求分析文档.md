## 1. 选题背景与项目定位

### 1.1 背景
传统招聘中，"海投简历 + 人工筛岗"效率低、双方信息不对称：
- 求职者：不清楚自己与岗位的匹配程度，投递命中率低；
- 招聘方：简历量大，人工筛选成本高、标准不一。

### 1.2 项目定位
采集**招聘平台公开岗位数据**，围绕**简历**构建一个人岗匹配推荐系统：
> 输入一份简历 → 输出「匹配评分 Top-N 岗位推荐 + 岗位聚类画像 + 智能问答」。
> 让"找什么工作、岗位是否合适、为什么合适"三个问题有据可依。

### 1.3 系统边界（本期不做）
- 不做在线投递/简历解析服务，不做双向社交功能；
- 简历输入本期以「文本粘贴 / PDF 提取」为主；
- 数据仅用于教学实训，非商业用途。

## 3. 业务问题拆解（四问对齐课程主线）

课程要求围绕"评分 / 匹配 / 聚类 / 大模型"四个业务问题展开，映射如下：

| 业务问题 | 用户诉求 | 输入→输出 | 技术方案 | 评估指标 |
|---------|---------|----------|---------|---------|
| ① 匹配评分（评分模型） | 这个岗位"适不适合我" | **<简历, 岗位> 配对** → 是否匹配(0/1) + 匹配分(0-100) | 业务规则构造标签 + 12 维匹配特征 + Logistic/SVM/RF/**XGBoost** | Accuracy / Precision / Recall / F1 / ROC-AUC |
| ② 人岗匹配 | 我适合什么岗位/岗位适合我吗 | 简历+岗位 → 匹配度分、Top-N推荐 | 技能 TF-IDF+余弦 + 加权匹配公式（可解释） | 召回Top-k命中、样例人工核验 |
| ③ 岗位聚类画像 | 岗位分成哪几类、我属于哪类 | 岗位特征 → 簇标签+画像 | K-Means(肘部法/轮廓系数) + PCA/t-SNE | 轮廓系数、簇命名可读性 |
| ④ 大模型问答 | 自然语言问岗位/求职建议 | 问题 → 带溯源的答案+推荐 | RAG(向量库) + Agent(**Function Calling，DeepSeek API**) | 召回Top-k、溯源正确率 |

> **①与②的分工**：①是**数据驱动的精排模型**（从 15.4 万条配对样本学习，回答"配不配、多少分"）；②是**可解释的加权公式推荐**（人工设定各维度权重，回答"为什么推荐它"）。系统里先用硬门槛召回候选岗位，再用①排序，用②给出理由与可解释分解。

## 4. 用户角色与典型场景

### 4.1 用户角色
1. **求职者（主用户）**：应届生/社招人群，需快速定位合适岗位；
2. **招聘分析师 / HR（次用户）**：观察岗位市场分布（薪酬、城市、行业聚类）。

### 4.2 典型场景（故事化）
- 场景A：应届生小张粘贴简历，系统给出 80 分的「数据分析师」岗位并说明：技能相似度 0.72、学历符合、经验差 1 年——为什么匹配；
- 场景B：HR 想了解"福州/厦门 Java 岗薪酬分布"，用自然语言提问，系统检索岗位库给出带来源的统计回答；
- 场景C：求职者浏览"岗位族谱"，看到系统把岗位聚成「研发/数据/产品/运营/职能」等画像簇，了解市场结构。

## 5. 数据源选定与采集方案（任务2 前置设计）

### 5.1 数据源对比与最终选定

| 数据源 | 优点 | 缺点 | 结论 |
|--------|------|------|------|
| 前程无忧 51job | 分页规整、字段较全、理论反爬温和 | **实测不可用**：登录墙 + 阿里云 WAF 滑块验证，无法稳定翻页 | ❌ 尝试后放弃（详见下方切换记录） |
| **智联招聘（zhaopin.com）** ✅ | 字段全（薪资/经验/学历/技能标签/职位描述）、岗位质量高、列表页可滚动加载 | 动态渲染（SPA）+ 部分接口校验，需真实浏览器抓取 | **✅ 主数据源（最终采用）** |
| BOSS直聘 | 数据新 | 强反爬、强制登录、动态渲染 | 备选（未启用） |
| 开源数据集/模拟数据 | 无爬取风险 | 非实时、真实性需核验 | 兜底（未启用） |

> **数据源切换记录（2026-09-08）**：按原方案先用 requests + BeautifulSoup 抓取 51job，实测被登录墙与阿里云 WAF 滑块拦截，多次尝试（含降低频率、更换请求头）仍无法稳定分页。
> 因此**切换为智联招聘**，改用 **Selenium 驱动真实 Chrome**（复用本地浏览器会话，符合"动态页用 Selenium/Playwright"的课程允许范围）完成分页抓取，最终采集 12,355 条有效岗位数据。

### 5.4 反爬与合规策略（设计目标 vs 实现情况）

| 措施 | 设计要求 | 实现情况 |
|---|---|---|
| 动态页渲染 | 用 Selenium/Playwright 驱动真实浏览器 | ✅ 已实现：Selenium + 真实 Chrome（远程调试端口复用本地会话） |

| 随机 User-Agent | 轮换请求头降低识别风险 | ⚠️ 待补：当前依赖真实浏览器默认 UA（未做轮换），列为任务2 补做项 |
| 失败重试 | 指数退避重试（≤3 次） | ⚠️ 待补：当前遇异常跳过并继续，未实现自动重试，列为任务2 补做项 |
| 并发控制 | 单城市单页串行、不并发 | ✅ 已实现：全程串行抓取 |
| 合规 | 遵守 robots.txt 与服务条款，仅采集公开信息 | ✅ 仅采集公开岗位信息；**不采集求职者个人敏感信息**；测试简历一律为模拟生成（`scripts/jianlishengcheng.py`） |

### 5.5 兜底方案（实际执行结果）

原计划：若主数据源不足 1 万条则切换城市/关键词、启用备选源、最后用开源数据补充。

实际执行：**主数据源 51job 不可用 → 切换为智联招聘**（见 §5.1 切换记录），通过多城市 × 多关键词组合分页抓取，最终 **12,355 条**达标，**未启用**开源数据集兜底。

| 机器学习 | scikit-learn（TF-IDF/Logistic/SVM/RF/K-Means/PCA）+ **xgboost** | 课程指定模型全覆盖（评分模型已上线 XGBoost） |

| 向量库 | Chroma（备 FAISS/Milvus） | 本地轻量起步，容量不足再迁移 |
| 大模型 | **DeepSeek API**（OpenAI 兼容协议：`base_url=https://api.deepseek.com`，模型 `deepseek-flash`；API Key 存 `.env` 不入库） | 官方支持 **Tool Calls（Function Calling）** 与 JSON 输出，可直接复用 `openai` SDK；中文理解/生成能力强、调用成本低，满足 RAG 问答 + Agent 工具调用需求（文档：https://api-docs.deepseek.com/ ） |
| 后端 | FastAPI + uvicorn | 四类 API（评分/匹配/聚类/对话） |
| 前端 | Streamlit（备 Vue3） | 快速演示、3天集成时间紧 |
| 部署 | Docker + docker-compose + 云服务器 | 课程指定 |
| 版本控制 | Git + GitHub（zhengqing798/zq） | 团队协作 + 答辩核验 |

### 7.3 人岗匹配方案预设计（任务6 预告）
匹配分 = `w1·技能相似度 + w2·学历匹配 + w3·经验匹配 + w4·薪资匹配 + w5·城市匹配`，
其中技能相似度 = 简历技能词集与岗位技能词集的 TF-IDF 加权余弦相似度；各 w 初始可设为
0.4/0.2/0.2/0.1/0.1，最终在任务6中以样例调优并记录版本。
