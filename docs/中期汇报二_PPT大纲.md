### P9 任务7-1：K-Means 定 K（课程要求"肘部法/轮廓系数定 K"）★
- 特征：技能 Top-60（0/1）+ 职能大类（9 类）；**不做标准化**，每块用 `1/√维度` 加权
  - （踩坑记录：早期对 0/1 块做标准化，轮廓系数只有 0.04–0.07、K 最优变成 2，属于错误处理）
- **定 K 曲线（务必上屏）**：

| K | inertia | 轮廓系数 |
|---|---|---|
| 2 | 602.7 | 0.4393 |
| 5 | **312.0（肘部）** | 0.6130 |
| 8 | 223.9 | 0.6633 |
| **9** | **203.0** | **0.6735 ← 峰值** |
| 10 | 193.3 | 0.5193（**断崖**） |

- **指标定义要讲清**：
  - `inertia`（簇内平方和）= 各点到所属质心的距离平方和，**越小越紧凑，但 K 越大必然越小 → 只能找拐点（肘部法）**
  - `轮廓系数` = `(b−a)/max(a,b)`，a=到本簇其他点平均距离、b=到最近邻簇平均距离，**−1~1，越大越好，不随 K 单调 → 可用来选 K**
  - `ARI`（调整兰德指数）= 两次聚类划分的一致性，**1.0000 = 换随机种子结果完全一致 → 结果可复现不是碰运气**
- **肘部法与轮廓系数不一致（K=5 vs K=9）要主动说明取舍**：优先看轮廓系数（要"簇间分得开、能命名"），且 K=9 时 inertia 仍在单调下降、没有恶化 → **定 K=9**

### P10 任务7-2：PCA/t-SNE 可视化与簇命名（课程要求"降维可视化并解读命名类别"）

### P13 任务8-2：评分模型 vs 匹配规则（实测，非空谈）

## 五、Q&A 预案（老师最可能问的 10 个问题）

| # | 问题 | 建议回答要点 |
|---|---|---|
| 1 | **没有人工标注，你的指标可信吗？** | 不可信的部分我们没宣称。评分模型的标签是规则生成的，所以我们明确说指标反映"对规则的拟合"而非"真实匹配力"；匹配用代理指标（大类一致率等），并算了 ±2.2pp 噪声带，只认可超出噪声带的差异。**报告里写了"不能宣称准确率 X%"**。 |
| 2 | **为什么线上用规则不用模型？** | 三个原因：① 规则 0.17s、模型要花约 1 分钟构特征；② 规则能输出六维分明细和推荐理由，可解释；③ 任务8 实测两者 NDCG@10 基本持平（0.7241 vs 0.7250）、Spearman 0.9909，说明模型学到的就是规则，**没有牺牲效果的换法**。 |
| 3 | **207,640 个配对哪来的？是真实数据吗？** | 是候选配对表 `匹配样本_标签数据.csv` 的行数。组成：同城对全量 132,640 + 每份简历抽样 150 个跨城对（500×150=75,000），种子 42。**"真实配对"= 真实数据的组合**，但简历侧是合成的、标签是规则算的，这两个事实我们在文档里都写明了。 |
| 4 | **K 为什么是 9？肘部法不是说 5 吗？** | 两个指标不一致是常态：肘部法看紧凑度（K=5）、轮廓系数看分离度（K=9 峰值 0.6735，K=10 断崖跌到 0.5193）。我们优先看轮廓系数，因为业务上要的是"簇之间分得开、能命名"，且 K=9 时 inertia 仍在单调下降没恶化。**这个取舍在文档里写清楚了。** |
| 5 | **轮廓系数 0.67 算好吗？** | 对 0/1 稀疏特征 + 职能大类这种数据，0.5 以上就算结构清晰。但要主动承认：**簇间仍有重叠**，51.45% 落在「其他」巨簇就是证据，所以我们做了二阶细分，并把它列为局限。 |
| 6 | **TF-IDF 余弦为什么最后只占 40%？** | 课程要求实现它，我们实现了并在 207,640 个配对上对比。实测 TF-IDF 在本数据上**没有提升**：IDF 让 Python/SQL 这类高频技能权重最低，分数被整体压低（余弦均值 1.90 vs 覆盖率 4.13），且零值率三者完全相同（83.6%）。所以用融合，主体交给尺度更合适的覆盖率。**如果老师要求纯余弦，改两个常数就能一键切换。** |
| 7 | **RAG 的 P@5 只有 0.353，是不是很差？** | 分两层说：① 纯语义 0.147 是真实暴露的问题，我们通过分类型路由 + 城市过滤提到 0.353，提升 140%；② 剩余偏低有两类原因——**真值集合很大**（"厦门 Java"可能几十个岗位，Top-5 最多命中 5 个），所以 P@5 是上限受限的；结论类问题的**溯源正确率其实接近 1.000**。此外我们如实说明：**真值由规则计算，没有人工金标**。 |
| 8 | **Prompt 版本记录是硬要求，你们的迭代是真的吗？** | 是真的，而且有证据链：v3 → v4 的动因来自 v3 的调用日志——30 问里有 3 条完全不调工具。我们补了 `search_kb` 结论卡检索工具后，有来源率 90%→97%、不用工具的问题 3→1。**每一版的实测数字都在 `docs/prompt版本记录.md` 里，可现场翻。** |
| 9 | **数据只覆盖 16 个城市，结论有代表性吗？** | 没有全国代表性，我们在文档和 Agent 回答里都明确声明了覆盖范围（16 城 / 福建、浙江、江苏、安徽）。Agent 被问到北京时会**先查城市清单再如实说查不到**，而不是编一个岗位。 |
| 10 | **第 3 周怎么保证能做完？** | 任务6/7/8/10 已完成并留了可复现脚本，第 3 周聚焦：任务11 前后端集成（后端 API 已具备匹配/推荐/对话能力，缺接口封装与前端页面）、任务12 Docker + 云服务器、任务14 文档与模拟答辩。风险主要是部署环境，已提前验证本地依赖可复现。 |
