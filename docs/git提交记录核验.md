# Git 提交记录核验台账

> 对应《需求分析文档》§2.2「**每日 Git 提交与同步**：全员提交 ｜ 李文庆 检查 ｜ 提交信息统一格式 `任务X: 一句话说明`」。
> 本文件是该项要求的**可审计凭证**：从仓库第一个提交开始，逐条列出全部提交并给出核验结论。
> 台账由脚本自动生成，**不手抄**：`python scripts/check_git.py --write`

---

## 一、约定（每次 git 之后必须执行）

| 步骤 | 动作 | 命令 |
|---|---|---|
| 1 | 提交 | `git add <文件>; git commit -m "任务X: 一句话说明"` |
| 2 | 推送 | `git push origin main` |
| 3 | **核验并记录** | `python scripts/check_git.py --write` |

**第 3 步是硬性动作**：核验结果（当前 HEAD、本地与远端是否一致、工作区是否干净）会写进 §3 与 §6，
提交记录台账（§4）同步刷新。这样"提交有没有真的推上去""历史有没有被动过"不靠记忆，靠文件。

两条补充约定：

1. **台账自身的更新要再提交一次**。因为台账里会记录"核验时的 HEAD"，所以完整流程是
   `提交代码 → push → 跑核验脚本 → 再提交台账 → push`。因此 §3 显示的 HEAD 可能比当前 HEAD
   **早 1 个提交**（即台账自身那次提交），属正常现象，不代表漏推。
2. **工具/流程类提交的前缀**：§2.2 规定格式为 `任务X: 一句话说明`。核验脚本、台账这类跨任务的流程文档，
   本仓库统一用 **`任务14:`**（文档与答辩）前缀，以便与功能提交区分。若团队另有约定，改本行即可。

---

## 二、核验的五件事

| # | 核验项 | 判定标准 |
|---|---|---|
| ① | 工作区是否干净 | `git status --porcelain` 为空；有未提交改动会在 §3 列出明细。**台账文件自身的待写入改动不计入**（脚本马上就会改写它，计入只会产生噪音） |
| ② | 本地与远端是否一致 | `git rev-parse HEAD` == `origin/main` |
| ③ | 有无未推送 / 未拉取提交 | `main ^origin/main` 与 `origin/main ^main` 均为空 |
| ④ | 历史是否完整可达远端 | 逐个提交检查是否在 `git rev-list origin/main` 集合内（防 force push / 只在本地） |
| ⑤ | 提交信息是否符合 `任务X:` 格式 | 正则 `^任务\s*\d+\s*[:：]` |
