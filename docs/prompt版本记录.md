# Prompt 版本记录 —— 任务10 Agent 智能体

> 课程 M2 验收要求「Prompt 有版本记录」。本文件记录每一版 Prompt 的改动内容、原因与**实测效果**。
> 当前生效版本写在 `src/agent/prompts.py` 的 `PROMPT_VERSION`；Agent 的缓存键包含版本号，改版后旧缓存自动失效。

| 版本 | 日期 | 状态 | 改动内容 | 改动原因 | 实测效果 |
|---|---|---|---|---|---|
| **v1** | 2026-09-14 | 设计稿（未落地） | 起草：角色设定 + 6 个工具说明 + 「只依据工具数据回答、标注来源、不确定就直说」 | 需要一个"不编数字"的数据问答助手 | 仅评审用，未实际调用 |
| **v2** | 2026-09-14 | 已被 v3 取代 | 在 v1 基础上补齐 7 条硬性要求：① 来源标注格式；② `ok=false` 时必须直说没查到；③ 推荐要给依据；④ 主动声明已知数据局限（16 城/24.69% 经验错位/无人工金标）；⑤ 中文分点、先结论后依据；⑥ 不输出 JSON 细节；⑦ 声明能力边界 | v1 在"诚实性"上约束不够——大模型容易用行业常识补全查不到的数据 | 7 条约束生效：示例问答中数字均带来源、能力边界问题如实回答"未覆盖" |
| **v3（当前）** | 2026-09-14 | ✅ 生效 | ① 工具从 6 个增到 8 个：新增 **`salary_rank`**（各城市薪资排名）与 **`city_list`**（覆盖城市清单）；② 新增规则 4：「同一个问题最多调用同一个工具 2 次；需要逐项对比时优先用聚合工具」 | v2 实测暴露问题：问「薪资最高的城市是哪个」时，模型**逐城调用 `salary_stats` 12 次**并撞上工具上限（12 次），prompt tokens 高达 9,330，回答质量还不稳定 | 同一问题（示例 3）：工具调用 **12 次 → 2 次**、prompt tokens **9,330 → 4,182**、耗时 7.1s → 3.8s；「北京有没有岗位」改为先调 `city_list` 再如实回答未覆盖 |

## 一、v3 的实测对照（同一批 7 条示例问题）

| 示例 | v2 工具调用 | v3 工具调用 | v2 prompt tokens | v3 prompt tokens |
|---|---|---|---|---|
| 1 岗位检索 + 统计 | search_jobs、salary_stats | search_jobs、salary_stats | 3,507 | 4,043 |
| 2 数值条件筛选 | filter_jobs | filter_jobs | 3,201 | 3,731 |
| **3 统计类（哪个城市薪资最高）** | **salary_stats × 12（撞上限）** | **salary_stats、salary_rank** | **9,330** | **4,182** |
| 4 聚类画像 | cluster_profile × 2 | cluster_profile × 2 | 3,884 | 4,408 |
| 5 人岗匹配（贴简历） | match_resume、search_jobs、filter_jobs、salary_stats | match_resume、filter_jobs、salary_stats | 4,683 | 4,671 |
| 6 知识库自述 | kb_stats | kb_stats | 3,037 | 3,565 |
| 7 能力边界（不存在的城市） | kb_stats、filter_jobs（失败） | **city_list** | 3,234 | 3,661 |

> 说明：v3 的 prompt tokens 略高是正常的——系统提示里多了 2 个工具说明（工具描述也计入 prompt）。
> 关键收益是**工具调用次数与总 token 的大幅下降**，以及回答稳定性的提升。

## 二、从这一轮迭代得到的结论（写进《大模型应用文档》）

1. **工具粒度决定 Agent 的调用轮数**：把"逐项查询"做成聚合工具（`salary_rank`），比在 Prompt 里反复叮嘱"不要重复调用"更有效。
2. **Prompt 约束要可验证**：把"不许编数字""没查到要直说"写成硬性规则后，示例问答里数字全部带来源，边界问题如实承认未覆盖。
3. **版本号要进缓存键**：否则改完 Prompt 仍会命中旧答案，评估结论会被污染。
