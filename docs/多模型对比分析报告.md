## 一、三类模型概览（不做「硬凑同一个指标」）

三类模型的目标与评价方式本来就**不同质**：评分模型是**有监督回归/分类**（测误差），匹配模型是**规则打分 + 排序**（测推荐质量与响应时间），聚类模型是**无监督分簇**（测簇结构与可解释性）。因此本节先如实列出各自的指标，再在第二节做**唯一真正可比**的实验。

| 模型 | 任务类型 | 目标/输入 | 关键指标 | 主口径结果 | 用途 | 局限 |
|---|---|---|---|---|---|---|
| 评分模型（任务5 XGBoost） | 有监督回归 + 二分类 | 输入 36 维特征，预测规则总分 0–100 与是否匹配（≥65） | MAE / RMSE / R² / PR-AUC / NDCG@10 | 噪声标签 MAE 0.8266、R² 0.9658；T2 PR-AUC 0.9652、NDCG@10 0.8672 | 批量打分/离线复现规则；作为规则的加速与交叉验证 | 标签由规则生成（蒸馏），指标反映对规则的拟合而非真实匹配力 |
| 匹配规则（任务6 六维加权） | 规则打分 + Top-N 排序 | 任意简历（粘贴/PDF）→ 解析 → 与 8,836 个岗位逐对算分 | Top-N 排序质量、岗位大类一致率、响应时间 | Top-10 岗位大类一致率 54.95%%（v2 权重）、全量打分 0.17s | 在线推荐主链路（可解释：6 维分 + 推荐理由） | 规则口径由人工设定；非 IT 岗可能进 Top-N；无人工金标验证 |
| 聚类模型（任务7 K-Means） | 无监督聚类 | 输入技能 Top-60 + 职能大类（9）→ 岗位分簇 | 轮廓系数 / inertia / ARI 稳定性 | K=9（轮廓峰值 0.6735，肘部法 K=5）；ARI 1.0000；最大簇再做二阶细分 K=8 | 岗位画像、粗筛候选集、簇命名用于前端展示 | 轮廓系数 0.44–0.67 但簇间有重叠；51%% 的「其他」岗位需二阶细分 |

## 二、唯一可比的实验：评分模型 vs 匹配规则

**设计**：在同一批候选配对（`匹配特征_全量样本.csv` 的 207,640 行，主口径按简历分组）上，让**评分模型（任务5 XGBoost）**与**匹配规则（任务6，v1 权重口径）**分别打分，按简历取 Top-10 比较。

| 指标 | 结果 | 含义 |
|---|---|---|
| 逐简历 Top-10 重合度（均值） | **0.788** | 两个方法推荐的 10 个岗位平均有 79% 重合 |
| 重合度分布 | 最小 0.111、中位 0.818、最大 1.000 | 逐份简历差异见 `多模型对比_重合度.csv` |
| 逐简历 Spearman 分数相关（均值） | **0.9909** | 分数排序几乎一致，模型确实学到了规则的顺序 |
| NDCG@10（按规则标签为正样本） | 模型 **0.7241** vs 规则 **0.7250** | 模型与规则在 Top-10 内的排序质量相当 |
| 打分耗时 | 模型批量 0.1s / 207,640 行 ｜ 规则在线 **0.17s / 8,836 岗** | **规则更快**（模型还要先构造 36 维特征） |

**结论（与常见预期相反，如实记录）**：
1. 评分模型与匹配规则**高度一致**（Top-10 重合度 0.788、Spearman 0.9909）——这正是设计意图：标签本身就是规则生成的，模型是对规则的**蒸馏**；
2. **速度各有场景**：模型**批量预测**本身很快（0.1s / 207,640 行，特征已在内存），但**前提是特征已经构造好**——构造 36 维特征（含 3 个 TF-IDF 余弦）要跑约 1 分钟；而规则在线给一份新简历打分只要 **0.17s 且不需要特征工程**。因此**在线主链路用规则（任务6）**，模型适合「候选池固定、特征可预计算」的离线批量场景；
3. 两者都不是「绝对正误」：真正的瓶颈是**缺少人工金标**——只能证明两者一致，不能证明它们都判对了。

## 三、聚类模型（任务7）要点

- 特征：技能 Top-60 multi-hot + 职能大类 one-hot；**薪资/经验/学历只作为簇画像属性，不参与聚类**（把薪资作为特征的尝试会把簇按资历分层，已弃用）
- 定 K：肘部法 K=5，轮廓系数峰值 K=9（0.6735）→ 采用峰值；ARI = 1.0000（四个随机种子完全一致）
- 结果：一级 9 个簇（软件测试 16.44%、后端开发 10.25%、运维 8.37%、算法 4.93%、前端 2.42%、嵌入式 2.41%、产品 2.16%、数据分析 1.55%），另有一个占 **51.45%** 的「其他」巨簇；
- **二阶细分**：对巨簇只用技能再跑一次 K-Means（K=8），分出质量检验、供应链/物料、硬件仪器、数据统计、Java 后端、AI 应用等子簇（明细见 `岗位聚类_簇画像.csv` 与 `岗位聚类_标签.csv`）
- 完整方法与局限见 `data/processed/岗位聚类_说明.md`

## 四、分工与适用场景

| 环节 | 用哪个模型 | 理由 |
|---|---|---|
| 在线推荐主链路（用户输入简历→Top-N） | **匹配规则（任务6）** | 0.17s、可解释（6 维分 + 推荐理由）、无需特征工程 |
| 离线批量评估/口径校验 | **评分模型（任务5）** | 可批量预测，用于验证规则是否被模型复现（重合度 0.788） |
| 候选集粗筛、岗位画像、前端展示 | **聚类模型（任务7）** | 把 8,836 个岗位压成 9+8 个可读类别，便于浏览与筛选 |
| 未来换权重/换数据 | 规则改 `匹配权重表.csv`；模型需重新训练 | 规则改动成本更低 |

## 五、局限与如实说明

| # | 局限 | 说明 |
|---|---|---|
| 1 | **三类模型指标不同质** | 不存在一个能把 MAE、NDCG、轮廓系数放在一起比较的单一指标；本报告只做「分项列出 + 一个可比实验」 |
| 2 | **缺少人工金标** | 所有「相关性」证据都是代理指标（规则标签、岗位大类一致率）；无法回答「模型判得对不对」 |
| 3 | **评分模型与规则高度一致** | 重合度 0.788 说明模型没带来新信息，只带来「批量打分」的便利 |
| 4 | **聚类存在大簇** | 51.45%% 的岗位落在「其他」，二阶细分后仍有 68.6%% 未进一步分开（电商运营/客户支持等长尾职能混杂） |
| 5 | **模型推理不占优** | 在线场景下模型比规则慢（特征构造开销），未做特征缓存优化 |
