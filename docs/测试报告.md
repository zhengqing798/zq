## 一、测试策略

| 层次 | 手段 | 覆盖内容 |
|---|---|---|
| **接口层** | `TestClient`（进程内 ASGI） | 四类接口的 正常/边界/异常；契约字段断言；错误码与错误文案 |

## 三、口径一致性测试（本版重点）

### 3.1 线上特征构造 = 离线训练口径

`src/api/score_features.py --validate 10`：用**离线简历**复算 36 维特征，与训练时使用的
`data/processed/匹配特征_全量样本.csv` 逐列比对：

```
验证：10 份离线简历 × 其全部候选配对
比对单元格：65,376 ｜ 一致：65,376（100.0000%）
✅ 36 维特征与离线特征表完全一致（线上模型口径 = 离线训练口径）
```

**为什么必须测这一条**：任务5 的 `build_features.py` 是批量脚本，评分 API 需要"单对"能力。
如果在线复算的口径与训练时不同，模型分就会失真却**看不出来**。这条测试把"口径漂移"变成了可判定的事实。

### 3.2 规则口径与模型口径的一致性（业务层）

| 指标 | 值 | 来源 |
|---|---|---|
| Spearman 秩相关 | **0.9909** | 任务8 多模型对比（207,640 配对） |

## 五、缺陷记录与修复清单

测试过程中发现并修复 4 个真实缺陷（均已复测通过）：

| # | 缺陷 | 现象 | 根因 | 修复 | 复测 |
|---|---|---|---|---|---|
| 1 | 评分 API 模型口径不可用 | `TypeError: sequence item 0: expected str instance, list found` | `resume_seg.tokenize()` 返回 **list**，代码直接拿去做 `" ".join` 的成员 | 改为 `" ".join(tokenize(...))`，与离线分词列同形 | ✅ 双口径恢复，规则 85.36 / 模型 84.17 |
| 2 | 查簇画像 500 | `Services.tool() got multiple values for argument 'name'` | 服务层方法首参与业务参数**同名** `name` | 方法首参改名 `tool_name` | ✅ 200 |
| 3 | 簇列表混入对照方案 | 返回 22 个簇，含 K=5 对照与二阶细分，无法区分 | 解析 markdown 表格，未区分「方案」列 | 改读 `岗位聚类_簇画像.csv`，按**方案**分组，主方案取 K=9 | ✅ 簇数=9，合计岗位数 8836 |
| 4 | **`response_model` 静默吞字段** | `/api/cluster/list` 响应里没有 `方案/主方案/各方案` | Pydantic `ClusterResponse` **未声明**这些字段，FastAPI 按模型过滤输出 | 在 schema 中补声明 | ✅ 用例 25 通过 |
| 5 | **同一类缺陷复发**：`已存历史` 字段被吞 | 匹配/问答返回体里没有 `已存历史`（但历史**确实已入库**，统计计数为 1） | `MatchResponse`/`ChatResponse` 未声明该字段 | 同样补声明 | ✅ 前端用例 4 断言 `已存历史=True` 通过 |
| 6 | 测试自身缺陷：断言找错组件 | 前端 3 个用例失败（找不到"8836"/"还没有保存的简历"/"统计推断"） | 美化后这些文本在 `caption`/`info`/`warning` 里，不在 `markdown` | 新增 `all_text()` 汇总所有文本组件 | ✅ 7 项全绿 |
| 7 | 测试环境污染风险 | 用户体系用例会写数据库，可能污染 `data/app.db` | 未隔离测试库 | 新增 `tests/conftest.py`：`APP_DB` 指向临时库并清库 + 显式建表 | ✅ 真实库不受影响 |

> **缺陷 4、5 值得单独记**：它们是**同一类问题连续发生两次**——FastAPI 的 `response_model`
> 会把未声明字段**静默丢弃**，接口"看起来正常"但数据少了。
> 第一次靠接口测试发现，第二次靠前端 AppTest 发现。**教训：新增返回字段必须同步改 schema。**

## 七、结论

1. **四类业务接口 + 用户体系全部可用**，正常/边界/异常三条路径 **78 项用例全绿**（30.56 s）
2. **口径一致性有硬证据**：线上 36 维特征与离线训练表 **65,376/65,376 单元格完全一致**
3. **前后端真联调**：Streamlit 通过 HTTP 调 FastAPI，游客/登录两种态、完整业务链路（解析→保存→匹配→收藏）均无异常
4. **安全有专项断言**：口令 PBKDF2 加盐、**库内无明文**、越权改删一律拒绝、登出令牌立即失效、角色权限 403
5. **性能达标**：匹配 0.3 s（要求 <3 s）、对话缓存命中 <0.1 s
6. **测试反哺开发**：7 个缺陷中 5 个由测试发现（含 `response_model` 吞字段**连续复发两次**），说明"先写接口测试 + 前端无头测试"是值得的
7. **如实标注未覆盖项**：PDF 接口用例、并发压测、视觉回归、安全渗透、企业侧功能均未做，原因已列出
